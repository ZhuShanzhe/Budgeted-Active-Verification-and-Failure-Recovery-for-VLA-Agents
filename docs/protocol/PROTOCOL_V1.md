# 统一比较协议

## 1. 研究对象与比较单元

协议标识为 `bav-code-evidence-v1`。比较单元为同一任务、同一初始状态、同一策略、同一决策时点的验证问题。策略先执行动作块，随后验证动作效果；记录动作前后观察和状态。成功终止点也进入数据，不能只保留未完成任务的中间点。

主环境为 LIBERO；LIBERO-Plus 承担原生扰动扩展；ManiSkill3 承担第二环境数据生成。主策略为已下载的 OpenVLA-OFT Spatial checkpoint。AVA-VLA 4-in-1 作为跨策略接口与后续对照，不混入主 critic 的训练数据。AVA 与 OFT 的预训练任务范围不同，跨 critic 分布不等于基础策略从未见过任务。

主协议图像为 256×256；历史窗口最多 4 个决策点；动作块最多 8 步；LIBERO 初始化稳定 10 步。Spatial、Object/Goal、Long 的正式任务步数上限分别为 220、280、520；人为缩短采集不记作完整任务失败。

## 2. 数据划分与污染控制

本协议从既有试验之后开始冻结，不追溯宣称此前查看过的任务是未见测试。

| 数据范围 | 用途 |
|---|---|
| Spatial 任务 0–5，初始状态 20–34 | 训练：90 个独立原始状态根 |
| 同任务，初始状态 35–39 | 校准：30 个根，仅校准，不喂给 coding agent |
| 同任务，初始状态 40–44 | 开发：30 个根，调试、失败分析和程序迭代 |
| 同任务，初始状态 45–49 | 密封 ID 测试：30 个根 |
| Spatial 初始状态 0–19 | 已使用范围，标记为 prior development |
| Spatial 任务 6–9 | 开发用跨任务探针，不宣称正式未见任务测试 |
| LIBERO Object、Goal、Long | 外部 critic/router 的正式任务 OOD 候选，默认禁止读取/采集 |
| 全部 Spatial LIBERO-Plus | 开发 OOD；此前已查看 Spatial Plus，因此采取保守边界 |
| 其他三个套件的 LIBERO-Plus | 密封任务×扰动联合 OOD，不能单独归因于扰动 |
| 当前 ManiSkill3 演示回放 | development_external，不是正式跨环境测试集 |

同一原始根下的不同策略、随机扰动、查询和恢复分支必须属于同一划分。合成扰动不改变 root_id。LIBERO-Plus 原生变体使用其场景文件和初始文件构成独立根；当前同套件全部保持在同一角色，不将同一基础任务的变体随机拆分到训练/测试。

训练视觉扰动为模糊、亮度、分辨率；遮挡、传感器噪声、相机偏移不得进入训练或校准根。纯扰动 OOD 在密封的同任务初始状态上以 clean/perturbed 配对评测，避免与任务变化混在一起。

原始任务包含多个场景，但当前训练/测试主划分不是经过独立审核的“新场景/新物体”划分。场景、物体、策略、环境五类结果须分开命名；没有相应独立划分和样本时，不报告该类泛化结论。任务级 OOD 不自动证明场景级 OOD。

默认读取器和采集器拒绝 test 数据。`--allow-test` 是受信任评测操作者的显式开关，不交给生成程序。旧演示和旧 baseline 数据不会因为已下载就自动成为本协议训练集。

## 3. 可见信息与标签

critic 输入为任务语言、截至当前的 RGB/本体状态/已执行动作历史以及已经付费请求的证据。决策程序只接收风险、不确定性、证据充分性、剩余预算和工具状态等白名单字段。

仿真完整状态、对象真值、分割 ID、目标谓词、最终成败、扰动注入元数据和划分身份只在监督、分析或评测侧。离线 coding agent 可以获得开发集反馈，但运行时不得读取这些答案。数据文件的 public/private 分离是接口边界，不是对服务器 root 用户的安全隔离。

白盒动作 token 特征单独保存，不能与默认 RGB 黑盒轨道混用后仍声称输入一致。OFT/AVA 特征不能直接当作原 SAFE WidowX 特征使用。

## 4. 工具与成本

基础验证输入已经包含全局 RGB 和本体状态。因此对同一数据的 `global_rgb`、`proprio` 再次请求只表示额外处理通道，不是新增信息；同样，腕部图像是主 VLA 已使用的传感器输入。比较必须分清“策略已观测”和“验证器已处理”。

可运行工具包括全局图、固定中心裁剪、腕部图、额外固定相机、深度和本体状态。固定中心裁剪是管线参考，不是任务区域 grounding；固定相机不是机器人主动移动相机。强 VLM 和学习式分割保留 provider 接口，未配置时返回 unavailable。仿真真值分割和状态是 oracle 专用，不属于普通路由候选。

默认每个决策点预算 4 evidence units、最多 4 次查询；扫描预算为 0/1/2/4/8。单次图像或深度处理的代理单位为 1，本体状态为 0.125，学习式分割为 2，强 VLM 为 4。这些是固定的实验代理权重，不是实际 token、FLOPs 或人民币费用。

必须另外报告真实处理像素数、采集耗时、模型推理耗时、模型 token（配置真实 provider 后）、VLA 调用次数、恢复物理步数。当前没有物理相机动作，不能伪造相机移动成本。离线 HDF5 查询时间不等于在线感知延迟；验收中的日志时间不用于性能优越性比较。

预算由受信任 Runtime 扣除，先预留再执行；失败查询仍扣款；缺失工具不会伪造返回结果；重复查询不得重复获取免费信息。恢复分支记录 VLA 计算和物理步数，不把恢复成本藏在证据单位中。当前离线程序评测只记录恢复请求，并不执行闭环恢复；配置中的 max_recoveries 尚不代表已部署的闭环限制。

## 5. 指标与对照

当前基础程序包含不额外查询、固定单视角、固定多视角和不确定性路由。它们是接口对照，不等同于复现 SAFE、AHA 或论文方法。之前 baseline 的正式结果继续保留在 `docs/reproduction/`，不与新协议数据混表。

critic 必须声明目标：当前目标尚未满足，或者记录的后续轨迹在既定上限内失败。两者不能混为同一个“失败概率”。离线入口记录 Brier、接受覆盖率、接受样本风险、预算、错误和证据效果；未配置 critic 时这些风险指标为空。

工具证据效果以同一状态下固定 critic 的基准预测和查询后预测计算。相对于真值的 Brier 改善可以作为证据价值监督；单纯概率下降不是准确率提高。当前实现单工具相对基础观察的效果，组合查询的条件增益须按已获取证据集合另外评估。

正式论文评估还包括 AUROC/AUPRC、校准误差、报警提前量、风险—成本曲线、闭环成功与恢复率、跨任务/根级置信区间。当前采集验收不提供这些完整统计结论。阈值只从独立校准数据确定；修改 critic、输入工具或分布后不得沿用旧校准保证。conformal 的保证依赖假设，不能自动延伸到任意 OOD。

## 6. 更新边界

每次 episode 保存协议哈希、代码文件哈希、策略配置、仿真提交和随机种子，数据完成后写入校验清单。变更协议时使用新版本和新目录，原始数据不覆盖。参考程序阈值只是工程占位，不是已校准阈值。

全自动代码生成后端、通用代码沙箱、自动部署和闭环恢复控制尚未启用。候选程序经受限解释器运行；固定评测报告只输出通过/拒绝，不直接修改线上系统。正式测试不用于反复观察和改程序；迭代式回归闸门与最终一次性测试在正式运行前须进一步独立划分。
