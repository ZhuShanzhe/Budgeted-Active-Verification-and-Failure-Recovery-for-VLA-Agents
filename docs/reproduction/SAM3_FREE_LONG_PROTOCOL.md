# 不依赖 SAM3 的具身 Agent 长程评测协议

## 实验对象与范围

第一轮采用原始 LIBERO `libero_10` 的 10 个长任务，每任务使用公开初始状态索引 40，随机种子 7。统一使用 256×256 的全局与腕部 RGB、机器人自身状态，以及公开 Pi0.5 执行模型。此划分用于开发诊断，不是新建的训练/测试分布划分，也不宣称 OOD 泛化结果。

模型为 `lerobot/pi05_libero_finetuned_v044`，冻结 revision `8e174154ef5f6c60a8da12ae99c303d8963138c1`。权重、归一化和预处理文件整体使用，不能与 RLinf 格式权重或另一套动作统计混用。执行时关闭编译，采用 bfloat16、10 次 flow-matching 推理、最多 32 步动作段。

| 评测项 | 保留的机制 | 适配边界 |
|---|---|---|
| Fixed Pi0.5 | 完整任务指令、固定动作段执行 | 无上层 Agent；执行到物理预算上限。 |
| EmbodiedSkills AgentLoop | 公开组件、子任务计划、阶段约束、前置检查、有界执行、验证、恢复、共享上下文 | 使用公开 LIBERO/LeRobot 接口及其支持的执行模型；上层改为 DeepSeek。隐藏原生接口提供的成功谓词。这是适配机制评测，不是论文原模型原成绩复现。 |
| Thea port | 公开 Harness、Task Notes、上下文管理、独立 ModelEvaluator、结果 exit code 与分段重试 | 将冻结 Pi0.5 封装成子任务执行工具；没有复现完整 Scene Graph、真机技能和跨任务经验库。不得将此名称简写成完整 Thea 系统成绩。 |

CaP-Agent0、RPent 以及其他依赖 SAM3 的分支不运行；不等待授权，也不将删除感知工具后的结果作为完整系统成绩。Cortex 的完整仿真闭环未公开，不混入闭环任务成功率表。

## 统一规则

- 物理动作上限 520 步，预热 10 步不计入；相同任务—初态按哈希核对。每条轨迹重置环境和策略随机状态，包括模型加载之后再次重置。
- Agent 可以使用完整任务指令或当前子任务指令调用固定执行策略，但不能修改权重、写入物体位姿、重置 episode 或读取成功谓词。
- 每条轨迹最多 120 个 Agent 循环轮次、160 次模型调用、160 次采集；两个框架的单轮结构不同，另外报告实际调用、token 和延迟，不能只比较轮数。
- 决策采用 DeepSeek V4-Pro；视觉组件及验证器采用 DeepSeek Flash。V4-Pro 需要图像时，使用带来源说明的 Flash 转写，不把转写当真值。此设置不代表论文上层模型能力，也不代表开启推理模式的能力上限。
- 单次决策、直接视觉组件和验证输出上限统一为 2,048 token；图像转写统一为 1,536 token。Thea v1 使用了较低的单次上限，排除出最终配对表；v2 按统一上限重跑。EmbodiedSkills 原批次实际请求已符合统一上限，逐条核对后保留。
- API 使用预估费用上限；服务中断、权重/仿真加载异常单列为基础设施问题，不计为机器人任务失败。

## 真值隔离和评分

机器人操作产生的 reward、done、成功谓词、物体状态名称与位姿不进入 Agent 可见观察。公共结果中任务成功是 unknown，而不是强行标为 false。可信宿主单独记录每一步的仿真成功谓词，并在 Agent 终止后评分。对两种框架都不使用成功真值自动停止。

核心指标为停止时成功率、曾经成功率、首次成功步数、完成后再次失败、完成声明/验证结论、退出原因、动作数、模型与验证调用、token、延迟和费用。它们与论文采用自动成功停止的标准成功率不直接比较。

先以真实固定策略动作验收图像、状态、动作、归一化和仿真接口，再运行 Agent。验收与开发调试输出使用独立目录，不回填正式评测记录。最终报告同时列出计划样本数、实际完成数、有效样本数和基础设施排除数。

## 失效归因

日志定位首次视觉误判、错误子目标切换、历史证据丢失、过时信息复用、无效重试或任务破坏。底层策略失败、上层预算不足、被移除的 oracle 反馈和部署未包含的技能分别记录。只有跨阶段证据证明历史状态错误影响决策时才称为长程状态跟踪问题；只有对照干预支持时才给出因果解释。

实现：`bav/agent_audit/embodied_long.py`；汇总：`bav/agent_audit/summarize_embodied.py`。本文是执行协议，不是实验完成证明。

## 部署验收记录

独立环境为数据盘上的 `conda-envs/embodied-audit`：Python 3.12、PyTorch 2.8.0+cu128、LeRobot 0.4.4、MuJoCo 3.3.0、robosuite 1.4.1。Transformers 使用 LeRobot 指定的 `fix/lerobot_openpi` 分支，冻结提交 `dcddb970176382c0fcf4521b0c0e6fc15894dfe0`。未安装与本次推理无关的全部训练、可视化和硬件附加组件；是否可执行以真实仿真验收为准，不以包安装完成为准。

- LeRobot 0.4.4 的配置与工厂函数位于子模块，部署层只补充同一对象的导出别名，不改 Agent 或策略算法。
- 权重文件的 metadata 明确将词嵌入映射到共享的语言输出权重。部署层按发布者记录恢复该别名，再进行严格的完整参数加载；任何其他缺失参数均阻止评测。
- 该版本配置加载只通过 `cli_overrides` 应用策略参数；普通关键字不能确保覆盖。运行时再次断言关闭编译、32 步动作段、10 次推理，并保存实际完整配置。
- Thea 的执行后验证目标绑定到本次实际子任务指令，不将整个长任务未完成误当作中间子任务失败。
- 预热、加载异常和接口调试保留在独立 canary 目录，不能作为正式任务成绩。原始权重与上游源码保持不变。
- EmbodiedSkills 按固定任务编号拆分：原批次保留任务 0-4，独立 tail 批次执行 5-9。拆分监督器只读取已完成数量，不读取成功分数。未完成的后续启动目录不计入样本；汇总检查每个任务每个方法恰有一条有效轨迹。
- Thea v2 同理保留原批次任务 0-7、tail 批次任务 8-9。拆分按完成数量触发，不读取成绩；不混入 Thea v1 的低输出上限记录。
- 每条 Agent 轨迹费用上限最多 3 美元，同时受来源批次剩余总预算限制；实际有效运行均未触发费用上限。批次预算及实际调用账本保留，不能将批次预算写成单轨迹预算。
- EmbodiedSkills 任务 6 首次在动作执行前出现 HTTP 400。JSON 模式提示的检查原先误将图像 base64 中的字符当作文本提示；修正为检查可见文本后按原初态重跑。成功请求的提示语义与模型上限不变。该异常单列，不计作操作失败。
