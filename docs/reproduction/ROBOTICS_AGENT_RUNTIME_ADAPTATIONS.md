# 机器人操作 Agent：运行适配与实验边界

本轮范围是 LIBERO 机器人长任务，不运行论文中的无关领域。依赖、RPC、模型服务与数据接口允许修复；任务决策由各自的原生 Agent 流程产生，不替换为人工动作序列。所有结果称为“适配评测”，不声称论文原始配置完全复现。

## 保留的架构

| Agent | 保留的执行流程 | 部署差异 |
|---|---|---|
| RPent | 原生规划循环 → 公开分层记忆 → 观察/分割/反投影 → VLA 接触动作或直接控制 → 再观察与继续决策 | Pi0.5 本地策略；SAM3 换为 Grounding DINO+SAM2.1；DeepSeek 决策与 Flash 转写；任务真值不可见 |
| Zetta | 开发失败轨迹 → 原生 Diagnose/Propose → 冻结 critic/有序恢复规则 → 逐步 TemporalCritic → Role1 查看图像并批准 → RecoveryController 执行 → 返回策略 | 原生 RPC 换为本地线程安全接口；上层用 DeepSeek；原 Codex 会话改为显式重建 API 上下文；小规模候选实验，不冒充完整演化训练 |
| CaP-X / CaP-Agent0 单模型适配 | 原生九候选生成与综合 → Python 控制代码 → 原生技能库/感知/IK/抓取 → 执行反馈与视觉变化描述 → 原生代码重写/FINISH | 使用仓库原生支持的单模型集成分支，不是论文异构模型集成；保留 JOINT_POSITION、PyRoKi 和 Contact-GraspNet；SAM3 换为公开感知服务；代码只能使用数值计算与公开机器人 API |

Thea port 与 EmbodiedSkills 沿用已有报告；Thea port 仍明确标注缺少论文完整场景图和真机技能，不改名为整机复现。OpenETA 不在本次已完成成绩中。

## 运行错误与修复

| 部位 | 错误 | 修复与结果边界 |
|---|---|---|
| Zetta Role1 | 模型返回说明文字和 Markdown，原程序要求纯 JSON | 仅在该决策接口启用 JSON 输出并保留原生字段/权限/证据校验；canary 完成实际恢复动作。强制触发 canary 不计性能 |
| Zetta 离线阶段 | JSON 模式产生空白/长输出并截断；后续结果漏引必需的失败时序窗口 | 离线阶段恢复原生 JSON 提取方式；提供原校验失败反馈，要求模型重新引用实际读取的证据；未通过校验的结果不执行 |
| Zetta 证据来源 | 模型把未执行过的 `move_to`/IK 当作 Gen0 失败原因 | 补齐真实控制器来源：Gen0 仅执行冻结 Pi0.5 的五步动作段；可用恢复工具不等于已执行工具。错误诊断保留，不作为确定原因 |
| CaP 依赖 | 缺 MuJoCo、Numba；旧 PyOpenGL 不兼容 EGL | 独立环境安装 MuJoCo 3.3.0、Numba 0.61.2、PyOpenGL 3.1.10；不更换原关节控制器 |
| CaP 初态 | 设置公开初态后又调用 reset，覆盖选择 | 修正重置顺序，保存稳定后状态哈希；保留原十步稳定过程 |
| CaP 计数 | 只观察 `_step_once` 会遗漏直接关节运动 | 统一在 `LiberoHandle.step` 记录所有 8 维动作与逐步私有真值；早期漏计轨迹不纳入性能 |
| CaP API | 九候选同时连接时，单线程本地 HTTP 服务接收队列超时 | 换为并发连接接收，费用账本仍串行受锁保护；网络丢候选调试轮排除 |
| CaP 数值运行时 | ndarray 的 min/max 内部导入被数值白名单误拦截 | 允许 NumPy 内部 reduction 模块调用，仍禁止生成代码直接导入该模块、读取文件或仿真私有状态；受此问题污染的轮次单列 |

正常的感知无目标、生成代码错误、验证判断错误、合法动作失败与预算耗尽属于方法在当前部署下的表现；依赖缺失、漏计、协议解码和网络适配错误属于基础设施问题。两者不混算。

## 评分原则

记录原始动作、双视角观察、代码/工具调用、模型输出、实际成本、停止原因、逐步成功真值与运行修复。成功真值仅由宿主评分，不用于自动停止。短暂成功单独记录，不等同于稳定完成。

RPent 的十任务结果见 `RPENT_OPEN_LONG_RESULTS.md`。Zetta 的三个配对留出初态见 `ZETTA_ONLINE_RESULTS.md`；开发过的样本不再称独立测试。CaP 的原生闭环见 `CAPX_ONLINE_RESULTS.md`，使用原生 8000 步上限，而 VLA 对照为 520 步，两者不能混成同预算排行榜。CaP 原生上限计入十步重置稳定过程，私有评分另记稳定后的实际步数。

数值代码边界与真值隔离回归测试合计 17 项通过。CaP 内部布尔评分占位不作为任务真值；检查原生多轮提示构造确认它只传执行代码、stdout/stderr 和视觉反馈，不向决策模型传这些评分占位。原生汇总中的 `task_completed`/`reward` 不用于本报告计分。
